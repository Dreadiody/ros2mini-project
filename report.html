My design approach

I began by thinking about the robot as a set of rigid links and the motions that connect them. I used world as a stable reference, fixed the base to it, and arranged the arm links in a serial chain. At the end of the arm, I attached two separate sliding finger links to represent the gripper. This structure keeps the arm motion and gripper motion easy to identify in both the Xacro and the TF tree.

Why these joint types? I used revolute joints for the articulated arm because those links rotate about an axis. I used prismatic joints for the gripper fingers because they translate along an axis. I kept the finger joints as separate branches so their direction and travel limits can be specified independently.

The included model contains five revolute arm joints and two prismatic gripper joints. I describe the gripper separately from the arm so the function of each movable joint is clear.

Question 1 — Robot structure design

Question: Define the kinematic structure of the arm and label its joints and links.

Answer: I represented the root reference as world and attached the robot base, base_link, with the fixed joint base_joint. Five revolute joints connect the arm links sequentially. The final arm link, link_5, is the parent of the two prismatic gripper fingers.

world
└── base_joint (fixed) → base_link
    └── joint_1 → link_1
        └── joint_2 → link_2
            └── joint_3 → link_3
                └── joint_4 → link_4
                    └── joint_5 → link_5
                        ├── joint_6 (prismatic) → link_6
                        └── joint_7 (prismatic) → link_7

The complete model has nine links including the reference frame, one fixed joint, five revolute arm joints, and two prismatic gripper joints.

Question 2 — URDF link definition

Question: Define the links, including visual and collision geometry.

Answer: In my Xacro, base_link and link_1 through link_7 each have a visual element and a collision element. Their geometry references STL meshes in the package's meshes/ directory. Visual elements specify material colours for rendering in RViz2; collision elements describe the link shapes for collision-aware tools. The robot links also include inertial properties. The world link is a reference frame and does not need geometry.

Question 3 — Joint definition

Question: Define joint types, parent–child relationships, axes, and limits.

Answer: Each moving joint names its parent and child links, type of motion, axis, and allowed range. Revolute limits are angular values in radians. Prismatic limits are linear distances in metres. The Xacro also provides effort and velocity limits.

Question 4 — Assembly validation

Question: Assemble the links and joints into a complete URDF robot model.

Answer: I assembled the link meshes, inertial data, joint relationships, limits, and control declarations in robot_arm_urdf.urdf.xacro. The fixed base joint anchors the structure at world; the five arm joints form a connected chain and the gripper joints branch from link_5.

I built the package with colcon, expanded the Xacro, and checked the resulting URDF. The parser reported world as the root and showed the expected arm chain and gripper branches.

cd /home/echo/moveit2_ws
colcon build --packages-select robot_arm_urdf
source install/setup.bash
xacro src/robot_arm_urdf/urdf/robot_arm_urdf.urdf.xacro > /tmp/robot_arm.urdf
check_urdf /tmp/robot_arm.urdf

Question 5 — RViz2 visualization

Question: Load the robot model in RViz and verify the visualization.

Answer: I launched the model using display.launch.py, which starts robot_state_publisher, the Joint State Publisher GUI, and RViz2. In RViz2, I set the Fixed Frame to world and enabled RobotModel. The screenshot shows the robot geometry and the RobotModel status as OK.

The Joint State Publisher GUI can be used to preview different joint positions. This demonstrates the model's kinematic visualization; it does not simulate forces or physical contact.

source /opt/ros/humble/setup.bash
source /home/echo/moveit2_ws/install/setup.bash
ros2 launch robot_arm_urdf display.launch.py

Question 6 — TF tree verification

Question: Visualize and verify the robot's TF tree using ROS 2 tools.

Answer: I generated the frame report using tf2_tools view_frames. It lists eight frames: world, base_link, and link_1 through link_7. The tree shows the fixed base connection, the serial arm chain, and two gripper branches from link_5.
